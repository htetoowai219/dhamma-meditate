# Code Review: Phase 01 — Core Offline Audio & Timed Playback (`2026-11-25`)

- **Project Mode:** Prototype / MVP
- **Scope:** 39 files (Phase 01 full implementation; git not initialized)
- **Reviewer:** Fresh read-only subagent (`research` on `pro`)
- **Verdict:** Changes requested

## Summary
Phase 01 establishes a clean, well-structured Tracer Bullet foundation for `DhammaMeditate`: the pure-Kotlin monotonic timer and exponential fade curve are mathematically solid, `AudioFileImporter` safely isolates and probes audio into app-private storage, `RestrictedMeditationPlayer` cleanly strips seeking/skipping commands, and the flat Monastic Maroon & Saffron UI matches the design tokens without bloat. However, three Media3/Android service-lifecycle and state-synchronization flaws—missing transient audio focus suppression handling, stale `PlaybackStateStore` state after `Service.onDestroy()`, and broken cross-track error handling in `publishError()`—should be fixed before moving on.

## Major

### 🟠 Transient audio focus loss / ducking silences audio while the timer keeps counting down — `app/src/main/java/com/dhammameditate/playback/MeditationPlaybackService.kt:57-66`
- **Problem:**
  1. `MeditationPlaybackService` configures `ExoPlayer` with `C.AUDIO_CONTENT_TYPE_SPEECH` and `handleAudioFocus = true` (`:99-108`). In Media3 `1.5.1`, `AUDIO_CONTENT_TYPE_SPEECH` causes `AudioFocusManager` to pause on both `AUDIOFOCUS_LOSS_TRANSIENT` and `AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK` by setting `playbackSuppressionReason = Player.PLAYBACK_SUPPRESSION_REASON_TRANSIENT_AUDIO_FOCUS_LOSS` while keeping `playWhenReady = true`. `playerListener` only implements `onPlayWhenReadyChanged` (`:58-66`) and never observes `onPlaybackSuppressionReasonChanged`.
  2. `exoPlayer.play()` in `startSession()` (`:268-275`) and `resumeSession()` (`:322-325`) runs inside `withInternalPlayerChange { ... }`. If audio focus is denied synchronously at start/resume (e.g., during an active call), `ExoPlayer` sets `playWhenReady = false` while `isInternalPlayerChange == true`, so line `59` ignores the callback.
- **Impact:** During transient interruptions (notifications, navigation prompts, calls) or denied focus at start/resume, audio stops while `MeditationTimerEngine` keeps advancing, fading out, and even completing the session in silence—violating AC-5's audio-focus freeze/resume guarantee.
- **Suggested Fix:** Override `onPlaybackSuppressionReasonChanged(playbackSuppressionReason: Int)` in `playerListener` to pause the timer (`pauseTimerOnly()`) when suppressed while `PLAYING`/`FADING` and call `resumeTimerOnly()` when suppression clears to `PLAYBACK_SUPPRESSION_REASON_NONE` while `PAUSED` and `exoPlayer.playWhenReady` is `true`. After `withInternalPlayerChange` in `startSession()` and `resumeSession()`, check `!exoPlayer.playWhenReady || exoPlayer.playbackSuppressionReason != Player.PLAYBACK_SUPPRESSION_REASON_NONE` and pause the timer immediately if focus was denied/suppressed.

### 🟠 Service destruction while `PAUSED` leaves `PlaybackStateStore` stale and bricks `"Continue"` — `app/src/main/java/com/dhammameditate/playback/MeditationPlaybackService.kt:211-221`
- **Problem:** While `PAUSED`, Media3 detaches foreground status (`playWhenReady == false`), allowing Android to stop the background service and invoke `MeditationPlaybackService.onDestroy()` while the `Application`-scoped `PlaybackStateStore` stays alive. `onDestroy()` releases `exoPlayer` and `mediaSession` without resetting `stateStore`.
- **Impact:** Returning to the app still shows `ActiveSessionBanner` (`LibraryScreen`) and `"Paused"` + `"Continue"` (`PlayerScreen`). Tapping `"Continue"` spawns a fresh service whose new `MeditationTimerEngine` starts in `IDLE`; `resumeSession()` (`:316`) early-returns because status is not `PAUSED`, leaving `"Continue"` completely unresponsive until `"Stop & Reset"` is pressed.
- **Suggested Fix:** In `MeditationPlaybackService.onDestroy()`, if `timerEngine.currentStatus()` is active (`PLAYING`, `PAUSED`, or `FADING`), reset `stateStore` to an `IDLE` `PlaybackSnapshot` so the UI never displays a dead `Continue` state for a destroyed service.

### 🟠 `publishError()` in `startSession()` hides Track B's error banner and leaves Track A playing with a cancelled timer — `app/src/main/java/com/dhammameditate/playback/MeditationPlaybackService.kt:225-241`
- **Problem:** If Track A was previously loaded/playing (`PlaybackSnapshot.activeTrackId == "A"`) and the user opens Track B and taps `"Start Session"`, validation failure (`track == null`, missing/unreadable file, or invalid duration at `:225-241`) calls `publishError(...)` (`:439-451`) before updating `activeTrackId` (`:246`). `publishError()` cancels `tickJob`, resets `timerEngine`, and writes `status = IDLE` without pausing `exoPlayer` and while leaving `activeTrackId = "A"`. `PlayerViewModel.buildUiState()` (`PlayerViewModel.kt:116-120`) hides `errorMessage` whenever `playback.activeTrackId != trackId && playback.activeTrackId != null`.
- **Impact:** Track B's `PlayerScreen` silently swallows the error banner, and if Track A was playing, `exoPlayer` keeps playing Track A indefinitely with `tickJob` cancelled and `stateStore` reporting `IDLE`.
- **Suggested Fix:** Pass `failedTrackId = trackId` into `publishError(trackId, message)`, pause/reset `exoPlayer` (matching `onPlayerError` at `:81-85`), clear internal active fields, and record `activeTrackId = failedTrackId` (or a dedicated `errorTrackId` field on `PlaybackSnapshot`) so Track B always displays the inline `#D93025` error banner and previous audio never leaks.

## Minor & Nits
- 🟡 `app/src/main/java/com/dhammameditate/ui/library/LibraryViewModel.kt:86-91` — `deleteTrack()` fires async `playbackClient.stopIfActiveTrack(track.id)` (`startService`) and immediately deletes the Room row and audio file on `Dispatchers.IO`, racing `onStartCommand`. Stop playback synchronously/serially (and cancel any in-flight `startSession` coroutine for that track) before deleting the file.
- 🟡 `app/src/main/java/com/dhammameditate/MainActivity.kt:27-57` — `EXTRA_OPEN_ACTIVE_SESSION` is only handled in `onNewIntent()`. If `MainActivity` is recreated via `onCreate()` when tapping the media notification while `savedInstanceState` holds `selectedTrackId = null`, the user lands on `LibraryScreen` instead of `PlayerScreen`. Check `intent` in `onCreate()` too.
- 🟡 `app/src/main/java/com/dhammameditate/ui/player/PlayerScreen.kt:114-120` — `PlayerScreen` applies `WindowInsets.navigationBars` without `imePadding()` under `enableEdgeToEdge()`, so opening the soft keyboard on `"Custom minutes (min 1)"` can obscure the field and inline `#D93025` snap notice on compact screens.
- 🟡 `app/src/main/java/com/dhammameditate/ui/player/PlayerViewModel.kt:180-187` — Entering `"0"` in custom minutes shows `"Enter at least 1 minute"` and un-highlights the preset chip, yet `"Start Session"` remains enabled and launches using the previous `selectedDurationMs`. Disable `"Start Session"` while `"0"` is entered (or treat it as invalid).
- 🟡 `app/src/main/java/com/dhammameditate/ui/player/PlayerScreen.kt:89-112` — `askedNotificationPermission` uses `rememberSaveable` scoped to `PlayerScreen`, so navigating back to `LibraryScreen` disposes it and re-prompts on the next track if denied once. Hoist this flag to `MainActivity` or `AppContainer`.
- ⚪ `gradle/libs.versions.toml:38` — `kotlinx-coroutines-guava` is declared in `app/build.gradle.kts:76` but unused (`MeditationPlaybackService.kt:27-28` uses Guava `Futures.immediateFuture` directly).
- ⚪ `app/src/main/java/com/dhammameditate/ui/library/LibraryScreen.kt:103` — Prefer capturing a local `val` before null checks instead of `!!` inside click lambdas (same in `PlayerScreen.kt:183, 239`).
- ⚪ `app/src/main/java/com/dhammameditate/data/importer/AudioFileImporter.kt:70-71` — Assign `finalFile = targetFile` before `moveAtomically(tempFile, targetFile)` so partial stream-copy fallback writes are also cleaned up on error/cancellation.
- ⚪ `app/src/main/java/com/dhammameditate/playback/MeditationPlaybackService.kt:269` — Calling `exoPlayer.stop()` immediately before `exoPlayer.setMediaItem(...)` is redundant and momentarily pushes `ExoPlayer` through `STATE_IDLE`.

## Strengths
- **Drift-free, well-tested timing & fade core:** `MeditationTimerEngine.kt:24-180` derives elapsed/remaining time strictly from monotonic `SystemClock.elapsedRealtime()` deltas, handles `pause()` right at `0ms` cleanly (`:125-128`), and pairs with `FadeCurve.kt:5-30` and unit tests (`FadeCurveTest.kt`, `MeditationTimerEngineTest.kt`, `TimerValidationTest.kt`).
- **Defensive app-private import pipeline:** `AudioFileImporter.kt:49-100, 146-235` copies SAF URIs to `<uuid>.tmp`, blocks DRM and `video/` streams via `MediaExtractor`, falls back cleanly from `MediaMetadataRetriever` to `MediaExtractor` duration, releases native resources in `finally` blocks, and cleans up temp files; `TrackRepository.kt:21-24` prevents path traversal via `.name`.
- **Strict lock-screen/headset command restriction:** `RestrictedMeditationPlayer.kt:15-86` + `MeditationPlaybackService.kt:135-170` filter both `Player.Commands` and `MediaSession.ConnectionResult` down to Play/Pause, Stop, Metadata/Timeline, and `ACTION_STOP_RESET` while turning all seek/skip/speed methods into no-ops.
- **Clean flat UI & Burmese Unicode typography:** `ui/theme/Color.kt:5-20` and `ui/theme/Type.kt:9-67` adhere strictly to the flat Monastic Maroon & Saffron palette (`0.dp` button elevation, `1dp` `#D4D4D8` borders, zero gradients/emojis) with `1.45x–1.5x` line heights and tabular numerals (`tnum`).
