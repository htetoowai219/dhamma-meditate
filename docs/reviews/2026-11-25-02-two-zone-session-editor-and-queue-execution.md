- **Project Mode:** Prototype / MVP
- **Scope:** 30 code/test files (32 total including scope/plan docs, uncommitted on `main`)
- **Reviewer:** Fresh read-only review subagent (`Staff Code Reviewer`) + inline line-by-line verification

## Summary
Phase 02 is cleanly structured and closely follows the locked plan: Room's `MIGRATION_1_2` matches the generated `AppDatabase_Impl` schema, the two-zone `MeditationTimerEngine` and `MeditationPlaybackService` handle Intro-frozen countdowns, one-shot Intro-to-Main transitions, duplicate tracks, `STATE_ENDED` drift, and active-playback stop guards well, and the UI respects all flat Monastic Maroon & Saffron and Burmese-safe typography rules. Two **Major** correctness bugs should be fixed before merge: saved-session playback errors leak into Library Quick-Play (`PlayerScreen`), and adding or removing Main Queue tracks in `SessionEditorViewModel` can desynchronize `customMinutesInput`, `targetDurationMs`, and `capNotice`. Beyond those two fixes, there are 4 minor resilience/cleanup items and 1 nit.

## Major

### 🟠 Saved-session playback errors leak into Library Quick-Play — `app/src/main/java/com/dhammameditate/ui/player/PlayerViewModel.kt:125-135`
- **Problem:** When a saved session fails to start (e.g., missing or unreadable audio file), `MeditationPlaybackService.publishError` (`MeditationPlaybackService.kt:859-866`) emits `errorSessionId = sessionId`, `errorTrackId = null`, and `activeTrackId = null`. In `PlayerViewModel.buildUiState`, the error fallback condition at line 129 checks `(playback.errorTrackId == null && (isThisTrackLoaded || playback.activeTrackId == null))` without verifying `playback.errorSessionId == null` (unlike `SessionPlayerViewModel.kt:114`, which guards both IDs).
- **Impact:** If a saved session fails to start and the user navigates back without dismissing the banner, opening any Library track in Quick-Play (`PlayerScreen`) shows the unrelated saved session's error message.
- **Suggested Fix:** Guard the fallback branch in `PlayerViewModel.kt:129` with `playback.errorSessionId == null`:
  ```kotlin
  (playback.errorTrackId == null && playback.errorSessionId == null && (isThisTrackLoaded || playback.activeTrackId == null))
  ```

### 🟠 Main Queue edits desync `customMinutesInput`, `targetDurationMs`, and `capNotice` — `app/src/main/java/com/dhammameditate/ui/editor/SessionEditorViewModel.kt:198-223`, `269-296`
- **Problem:** Mutating the Main Queue while `customMinutesInput` is non-empty creates two inconsistent timer-validation states:
  1. **Capped custom input followed by adding a Main track:** Entering `"90"` on a 20:00 Main Queue caps `targetDurationMs` to `20:00` while keeping `customMinutesInput = "90"` and showing a cap notice. Adding another 20:00 Main track (`newMainTotal = 40:00`) keeps `customMinutesInput = "90"` and `targetDurationMs = 20:00` while clearing `capNotice = null` (`lines 215-222`). The custom field displays `90`, no cap notice is shown, the header shows `20:00`, and tapping **Save Session** persists `20:00`.
  2. **Invalid `"0"` input followed by adding or non-capping removal of a Main track:** Entering `"0"` sets `capNotice = "Enter at least 1 minute"` and disables **Save Session** (`hasInvalidCustomInput == true`). Adding a Main track (`line 220`) or removing a Main track that does not trigger a cap (`line 293`) clears `capNotice` to `null` while leaving `customMinutesInput = "0"`, leaving **Save Session** silently disabled with no error text.
- **Impact:** Breaks AC-2's clear timer validation contract in `SessionEditorScreen`—either saving a duration that contradicts the visible custom input field, or blocking Save with no visible reason.
- **Suggested Fix:**
  - In `addTrack(QueueZone.MAIN, ...)`, when `previousMainTotal > 0L` and `state.customMinutesInput.isNotEmpty()`, re-validate `state.customMinutesInput` against `newMainTotal`: preserve `"Enter at least 1 minute"` if `(toIntOrNull() ?: 0) < 1`; otherwise compute the updated `targetDurationMs` and `capNotice` via `TimerValidation.validateCustomMinutes(parsed, newMainTotal, TimerValidation.SCOPE_MAIN_QUEUE)`.
  - In `removeTrack(QueueZone.MAIN, ...)`, when `newMainTotal > 0L && !reconciled.wasCapped && state.customMinutesInput.isNotEmpty() && (state.customMinutesInput.toIntOrNull() ?: 0) < 1`, preserve `"Enter at least 1 minute"` instead of overwriting `capNotice` with `null`.

## Minor & Nits

- 🟡 `app/src/main/java/com/dhammameditate/playback/MeditationPlaybackService.kt:51`, `387-395`, `514-582` — `serviceScope` uses `Dispatchers.Main.immediate`, so `file.exists() || !file.canRead()` runs synchronously on the main thread for every track in `startQuickTrackSession` and `startSavedSession`. Wrap the file existence/readability checks in `withContext(Dispatchers.IO)` before configuring `exoPlayer` on Main.
- 🟡 `app/src/main/java/com/dhammameditate/ui/library/LibraryScreen.kt:212-252` — The track-deletion `AlertDialog` renders `summary.affectedSessions.forEach { ... }` inside a non-scrollable `Column`. A shared intro chant or bell referenced by many sessions can overflow on compact screens and clip warnings (`"Will need a new Main track before playing"`). Add `.verticalScroll(rememberScrollState())` to the dialog's outer `Column`.
- 🟡 `app/src/main/java/com/dhammameditate/MainActivity.kt:211-227`, `247-271`, `288-294` & `app/src/main/java/com/dhammameditate/ui/editor/SessionEditorScreen.kt:91`, `338` — Incrementing `editorCounter++` retains a new `SessionEditorViewModel` instance per New/Edit visit inside `MainActivity`'s `ViewModelStore` until the Activity finishes, and pressing Back while `uiState.isSaving` is `true` navigates away while `saveSession` is still in flight (its `onSaved` callback then overwrites `destination`). Guard `BackHandler` and the top-bar Back `IconButton` with `!uiState.isSaving` (and optionally reuse a fixed editor VM key with explicit `load`/`reset`).
- 🟡 `app/src/main/java/com/dhammameditate/data/repository/TrackRepository.kt:21-24` & `app/src/main/java/com/dhammameditate/data/local/QueueZone.kt:10-14` — Dead Phase 02 helpers: `TrackRepository.getTracksByIds` and `QueueZone.fromDbValue` have zero callers across `app/src`. Remove them (or route `SessionRepository` through `TrackRepository.getTracksByIds`).
- ⚪ `app/src/main/java/com/dhammameditate/playback/MeditationPlaybackService.kt:146-149`, `448-451`, `605-608` — In `onMediaItemTransition`'s `else` branch, if `timerEngine.tick()` happens to return `PlaybackStatus.COMPLETED`, route it directly to `finishSessionAtZero(currentTick)` instead of waiting up to 50ms for `tickJob`; also `exoPlayer.seekTo(0, 0L)` immediately after `exoPlayer.setMediaItems(..., startIndex = 0, startPositionMs = 0L)` + `prepare()` is redundant.
